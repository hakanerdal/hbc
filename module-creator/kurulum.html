Kurulum ve Gereksinimler

Bilgisayarı hazırlama · GitHub'dan alma · Canlıya gönderme

HBC ile mockup tasarlayıp Jira task metinlerini üretmek için Cursor kullanırsınız. Çalışmalarınız GitHub'da saklanır; böylece bilgisayar formatı veya silme durumunda kaybolmaz. Bu sayfa, bilgisayarda bir kez yapılacak kurulum ve günlük gönderme adımlarını özetler.

Aşağıda yeşil kutu = Cursor ile (önerilen). Turuncu kutu = Manuel (Cursor yetmezse veya tercih ederseniz).

1. Cursor kurulumu

  1. cursor.com adresinden Cursor'ı indirip kurun.
  2. Açılışta e-posta ile oturum açın (ekip hesabınız varsa onu kullanın).

2. Git kurulumu (bir kez)

Git, dosyaları GitHub ile eşitleyen küçük bir programdır. Komut ezberlemeniz gerekmez. Cursor önce kurulu mu diye bakar; yoksa kurulumda yardımcı olur.

Cursor ile

Önerilen. Sohbete yapıştırın:

Git kurulu mu kontrol et (git --version). Kuruluysa sürümü söyle, başka bir şey yapma. Kurulu değilse Windows'ta Git for Windows kurmama yardım et (winget veya resmi indirici). Kurulum onay isterse bana söyle. Bitince tekrar kontrol et.
Manuel
  1. git-scm.com/download/win adresinden Git for Windows indirin.
  2. Kurulumda varsayılanları kabul edin (Next / Next / Finish).
  3. İsterseniz Cursor'ı bir kez kapatıp açın.
GitHub hesabı Ekip size bir GitHub daveti göndermiş olmalı. İlk klon / gönderme sırasında tarayıcıda oturum açmanız istenebilir — GitHub üyeliğinize giriş yapın.

3. Python kurulumu (bir kez)

Mockup script'leri (Excel vb.) için Python gerekir. Cursor önce kurulu mu diye bakar; yoksa kurulumda yardımcı olur. Bu adımı proje indirmeden önce tamamlayın.

Cursor ile

Önerilen. Sohbete yapıştırın:

Python 3 kurulu mu kontrol et (python --version veya py -3 --version). Kuruluysa sürümü söyle. Kurulu değilse Windows'ta Python 3 kurmama yardım et (PATH'e ekle seçeneği açık olsun). HBC mockup script'leri için gerekirse openpyxl paketini de kur. Bitince tekrar kontrol et ve kısa özet ver.
Manuel
  1. python.org/downloads → Windows installer.
  2. Kurulumda Add python.exe to PATH kutusunu işaretleyin.
  3. Install Now. Bitince Cursor'ı yeniden açın.

4. Projeyi GitHub'dan alma ve Cursor'da açma (bir kez)

Bu adım bir kez yapılır. Klon = projenin kopyasını bilgisayarınıza indirmek. Sonraki günlerde tekrar klonlamazsınız; workspace'ten açıp (adım 5) güncelleme alırsınız (adım 6). Önce çalışma klasörünüzü seçin (ör. D:\worx), sonra aşağıdaki yollardan birini kullanın.

Adresler Repo (klon için): https://github.com/hakanerdal/hbc
Canlı site: https://hakanerdal.github.io/hbc/
Cursor ile

Önerilen. Sohbete yapıştırın (klasör yolunu gerekirse değiştirin):

D:\worx klasörüne https://github.com/hakanerdal/hbc reposunu klonla. Klon bitince hbc klasörünü Cursor'da Open Folder ile aç; sol dosya ağacında calismalarim görünür hale gelsin.

Başarılıysa sol panelde calismalarim listelenir.

Manuel

Sol taraftaki prompt işe yaramadıysa veya klasör açılmadıysa:

  1. Klon olduysa: File › Open Folder… (veya Add Folder to Workspace…) → doğrudan hbc klasörünü seçin.
  2. Klon da olmadıysa ekibe bildirin veya Cursor'a «klon neden başarısız?» diye sorun.

Windows klasöründe de kontrol: hbc içinde index.html ve calismalarim olmalı.

Daha önce zip / kopya ile aldıysanız (eski çalışmalarınız varsa) Eski klasördeki işlerinizi GitHub'a da taşımak için:
  1. Eski klasörün adını eski_hbc yapın (sağ tık → Yeniden adlandır).
  2. Yukarıdaki yeşil prompt ile yeni hbc klonunu alın ve Cursor'da açın.
  3. Cursor sohbetine şunu yapıştırın (yolları kendinize göre düzeltin):
    eski_hbc klasöründeki kendi çalışmalarımı yeni hbc'ye aktar. calismalarim altındaki çalışma klasörlerini kopyala; js/calismalar-meta.js listesine eksik girişleri ekle. Çakışan dosyada bana sor. Bitince ne kopyalandığını kısa özetle. Sonra Source Control ile Commit + Push yapabileceğimi söyle (push'u ben manuel yapacağım).
  4. Canlı sitede ve Cursor'da çalışmalarınızı görünce eski_hbc'yi silebilirsiniz (veya bir süre yedek tutun).

5. Workspace kaydetme (sonraki açılışlar için)

Her seferinde klasör aramayın. Bir kez workspace kaydedin; sonraki sefer kısayoldan açın.

  1. hbc Cursor'da açıkken: File › Save Workspace As… (Türkçe arayüzde «Çalışma Alanını Farklı Kaydet» benzeri).
  2. Dosya adı örn. hbc.code-workspace — kolay bulacağınız bir yere kaydedin (masaüstü veya D:\worx).
  3. Sonraki sefer:
    • File › Open Recent listesinden hbc (Workspace) seçin, veya
    • Kaydettiğiniz hbc.code-workspace dosyasına çift tıklayın — Cursor doğrudan HBC ile açılır.
  4. Yerelde mockup gezmek için: Dosya gezgininde hbc → index.html çift tıklayın (Chrome). Cursor'dan değil, Windows klasöründen açın.
  5. Günlük akış: Başlangıç rehberi — metni kopyala → Cursor sohbetine yapıştır.

6. Her çalışmada: önce pull, bitince push (manuel)

Ekip aynı projeyi paylaşıyor. Pull ve push'u Cursor sohbetine yaptırmayın — sol paneldeki Source Control ile kendiniz yapın.

6.1 Source Control'ü açın

Üstteki etkinlik çubuğunda dal / çatal ikonuna tıklayın (yeşil daire ile işaretli yer).

6.2 Ok yönleri ne anlama geliyor?

Sync düğmesinde veya alttaki durum çubuğunda ↓ / ↑ sayıları görünebilir:

  • ↓ (aşağı) — GitHub'da sizin bilgisayarınızda olmayan güncelleme var → çalışmadan önce alın.
  • ↑ (yukarı) — Sizin commit'iniz henüz GitHub'a gitmedi → gönderin.
  • Ok / sayı yoksa — Alınacak veya gönderilecek bir şey yok; ekstra işlem gerekmez.

6.3 Başlamadan önce — Pull (her zaman olmayabilir)

Başka biri push ettiyse Sync'te ↓ görünür. Görünüyorsa mavi Sync Changes'e basın (veya … → Pull). ↓ yoksa bu adımı atlayıp çalışmaya geçebilirsiniz.

6.4 Bitince — Commit

İşiniz bitince Source Control'de değişen dosyalar listelenir. Üstteki kutuya kısa bir mesaj yazın (ör. «Mockup eklendi») → mavi Commit'e basın.

6.5 Bitince — Push (GitHub'a gönder)

Commit'ten sonra Sync'te ↑ görünür. Sync Changes'e basın — değişiklikler GitHub'a gider; 1–3 dk sonra canlı site güncellenir (eskiyse Ctrl+F5).

Cursor ne için? Mockup üretmek, düzeltmek, yeni çalışma oluşturmak — sohbet burada. GitHub'a almak / göndermek — Source Control. Çakışma olursa (aşağıda) yine Cursor'a sorun.

İlk kez gönderiyorsanız ad / e-posta için 7. adıma bakın.

Çakışma olursa — Cursor'a sorun Pull veya push sırasında «conflict», «çakışma» veya «rejected» görürseniz: aynı dosyaya sizden önce başka biri de yazmış demektir. Komut ezberlemeyin — sohbete yapıştırın:
Cursor ile
Git çakışması / conflict var. Dosyaları bozmadan çöz: önce durumu kısaca Türkçe anlat, sonra çakışmayı gider. Benim son mockup / çalışma değişikliklerimi koru; ortak dosyalarda (ör. calismalar-meta.js) her iki tarafın eklemelerini birleştir. Commit veya push yapma — bitince sadece «çakışma çözüldü, Source Control'den Commit + Sync yap» yaz.
Önlem

Çakışmayı azaltmak için: işe başlamadan ↓ varsa Sync, aynı çalışma klasörüne aynı anda iki kişi girmeyin, bitince Commit + Sync ↑.

7. İlk gönderim — ad / e-posta (bir kez)

Git, «bu işi kim yaptı?» bilgisini ister. Bunu bir kez yaparsınız; sonraki gönderimlerde tekrar gerekmez. Ad ve e-postayı kendi bilgilerinizle yazın — e-posta olarak GitHub üyelik e-postanızı kullanın.

Cursor ile

Sohbete yapıştırın (sadece bu bir kerelik ayar):

Git'te adım ve e-postam kayıtlı mı kontrol et. Kayıtlıysa ekrana yaz, başka bir şey yapma. Kayıtlı değilse şunu kaydet (bilgisayardaki tüm projeler için geçerli olsun): Ad: Adınız Soyadınız E-posta: GitHub üyelik e-postanız Kaydettikten sonra tekrar kontrol edip bana göster.
Not

Bu adım dışında günlük pull / push için Cursor sohbeti kullanmayın — Source Control yeterli (adım 6).

Bu uyarıyı görürseniz Korkutucu değil. Cancel'a basın → yukarıdaki yeşil prompt'u yapıştırın → sonra adım 6 ile Commit + Sync yapın.

8. Canlı siteyi açma

  1. Tarayıcıda canlı siteyi açın: https://hakanerdal.github.io/hbc/
  2. Ana sayfada Çalışmalarım kartlarını görürsünüz; karttan mockup'a girersiniz.
  3. Jira'ya veya mail'e paylaşırken bu canlı linki kullanın (bilgisayarınızdaki file:// yolu değil).
Ne zaman lokal, ne zaman canlı? · Lokal (index.html çift tık): Siz tasarlarken hızlı bakış.
· Canlı (github.io): Müşteri / ekip / Jira paylaşımı; push sonrası güncel sürüm.
